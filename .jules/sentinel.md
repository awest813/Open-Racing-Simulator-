## 2024-05-18 - [CRITICAL] Prevent Command Injection and Path Traversal in Telemetry Module
**Vulnerability:** Command injection and path traversal due to unsanitized `filename` input in `TlmStartMonitoring` being used in `snprintf` to generate a shell script and shell command executed via `system()`.
**Learning:** Hardcoded calls to `system(buf)` where `buf` relies on external input can easily lead to arbitrary command execution. This pattern existed here to run gnuplot scripts.
**Prevention:** Avoid `system()` where possible. If inevitable, strongly sanitize any external input before constructing shell commands (e.g., allow only alphanumeric characters and underscores, discarding or replacing shell metacharacters and path delimiters).
## 2026-03-28 - Insecure Deserialization in PHP Auth Cookie
**Vulnerability:** The legacy PHP app (`torcs_racing_board`) used `unserialize()` to decode the "remember me" authentication cookie (`$_COOKIE[COOKIE_NAME]`), leading to a critical Insecure Deserialization (PHP Object Injection) vulnerability if an attacker tampered with the cookie string.
**Learning:** Legacy PHP codebases frequently rely on `serialize()` and `unserialize()` for state management (like cookies or session data) because JSON support wasn't natively ubiquitous until PHP 5.2.0. This allows attackers to instantiate arbitrary objects if gadget chains exist in the application.
**Prevention:** Never use `unserialize()` on untrusted user input. Always use secure, standard data interchange formats like `json_encode()` and `json_decode()` with the `assoc=true` parameter to ensure input is safely parsed as primitives or associative arrays, not executable objects.
